# Incident Response Runbook

## Purpose

Provide a repeatable workflow for triaging GuardDuty and Security Hub findings generated by the monitoring platform.

## 1. Validate the alert

- Record the finding ID, AWS account, Region, resource, severity, and timestamp.
- Confirm whether the finding is still active.
- Identify the originating service: GuardDuty, Security Hub control, or another integrated product.
- Check for related findings affecting the same identity, host, bucket, role, or network path.

## 2. Establish scope

Review CloudTrail activity around the finding time window and determine:

- Which IAM principal performed the activity
- Source IP address and user agent
- Affected AWS resources
- Whether privilege changes occurred
- Whether logging or security controls were disabled
- Whether activity occurred across multiple Regions

## 3. Contain

Containment depends on the affected resource and business impact. Examples include:

- Disable or restrict compromised credentials
- Revoke active sessions where appropriate
- Quarantine an EC2 instance with restrictive security groups
- Block malicious IPs at WAF, network firewall, or other enforcement points
- Remove unauthorized IAM policies or trust relationships
- Restore logging and monitoring controls if they were changed

Do not destroy evidence before collecting the information required for investigation.

## 4. Eradicate and recover

- Remove unauthorized changes
- Rotate affected credentials and secrets
- Rebuild compromised compute from trusted images when appropriate
- Validate security groups, IAM policies, bucket policies, KMS policies, and route changes
- Confirm GuardDuty, Security Hub, CloudTrail, and alert routing are healthy

## 5. Close and improve

Document:

- Root cause
- Timeline
- Affected resources and data
- Containment and recovery actions
- Detection gaps
- Preventive control improvements
- New alerting or automation opportunities

## Priority guidance

- **Critical:** active compromise, destructive behavior, credential theft, or high-impact data exposure
- **High:** likely malicious activity or a serious control failure requiring rapid investigation
- **Medium:** suspicious behavior that warrants timely triage and correlation
- **Low:** informational or low-confidence activity suitable for backlog review

This runbook is a portfolio reference and should be adapted to an organization's incident-response policy, legal requirements, and escalation procedures.
